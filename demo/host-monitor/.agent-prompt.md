# Agent brief — host-monitor demo

This file is the human-authored input to the lazytui loop. Everything else in
this directory (`tui.yml`) is produced by an AI coding agent reading this
prompt plus the output of `node js/app/tui.js --spec` and
`docs/metrics-producer.md`. Re-running that combination should regenerate a
functionally equivalent demo.

## What I want

A **btop-style system monitor** for the host machine — the kind of thing you
glance at while something is running. Live graphs of:

- overall **CPU** busy %,
- **memory** used %,
- **load average** (1-minute).

Plus quick access to a live process view (`top`) and a one-shot `ps` snapshot.

The point of this demo is to show that lazytui can be a real system monitor
**with no plugin code** — the graphs come entirely from the `metrics:`
producer feature (poll a shell command, extract a number, graph it).

## Shape — a new one

The two existing demo shapes in `DEMO.md` are both about Docker (Shape A =
produce the stack from scratch; Shape B = wrap an upstream Docker setup). This
demo is **neither**: it monitors the **host** directly, so there is no
container, no Dockerfile, no compose. Think of it as a third shape — *wrap the
host's own tools*. The only file the agent produces is `tui.yml`.

## Constraints

- **Linux.** Read `/proc/stat` (CPU) and `/proc/loadavg` (load); use `free`
  for memory. These are the portable, dependency-free sources — prefer them
  over `top`-output parsing, whose columns vary by version.
- **CPU busy %** must be an *instantaneous* rate: take two `/proc/stat`
  samples a fraction of a second apart and compute `100 * (busy_delta /
  total_delta)`. A single `/proc/stat` read is a since-boot average — wrong
  for a live graph. Do the arithmetic in the producer's shell command (e.g.
  `awk`), so the extractor just grabs one number.
- **Producer commands must be cwd-independent** one-liners (no separate script
  files to path-resolve) — they run via `sh -c` from wherever lazytui was
  launched.
- Type each metric so the axis scales right: CPU and memory are `percent`
  (0–100 axis); load is `number` (local-max axis).
- Poll every ~2 s (a touch slower for the process list — `ps` is heavier).
- Single-stream topics (one row) render with `row: _` on the `stats` panel.
- Multi-row topics (a process list, per-core, …) render with the `table`
  panel, sorted by a column; select a row and a `stats` pane with
  `select_from:` graphs that row's history.

## Out of scope (for this version)

- **Per-core CPU bars** as a stacked overlay (btop's signature grid). A per-core
  producer (`mpstat -P ALL`) + a `table` gives a browsable per-core list today;
  a single stacked graph of all cores at once is a `stats` aggregate mode that
  isn't built yet.
- Network / disk **throughput** — those are monotonic counters that need a
  rate (delta ÷ interval) the producer can't derive yet.
- Non-Linux hosts (macOS `/proc` differences, BSD `top`).
